# 0031 — Closing the gaps in Phases 11–13

**Status:** accepted · **Date:** 2026-10-16 · `plan.md` §7b

An audit after Phases 11–13 found unfinished tasks and some bugs. This
record covers what was added to finish them and why.

## Bugs fixed

- **Export from a query result ignored the chosen format.** Query results
  now export (and copy) in every format through `export_result` /
  `copy_rows`, using the same `transfer::RowWriter` as table exports.
- **JSON export was not valid JSON** (objects without keys). It is now an
  array of objects keyed by column; values stay strings so big numbers are
  exact, NULL is `null`, binary is `0x…`.
- **Table copy/export ignored the active filters.** `stream_table` applies
  them.
- **Binary values were exported from the 32-byte preview.** SQL formats now
  write every byte in each engine's syntax (`'\x…'::bytea`, `X'…'`, `0x…`).
- **MySQL binary columns showed as text** when the bytes happened to be
  valid UTF-8; binary-typed columns holding control characters are now
  binary.
- **Grid shortcuts used ⌘ only**, so Ctrl+C/Ctrl+A did nothing on Windows
  and Linux. `isModKey` (lib/platform.js) picks the platform's key.
- **A table's column layout wasn't remembered**: `ResultView` never declared
  its `layout` prop. It is now `v-model:layout`.
- **Bound numbers were floats**, so integers above 2^53 lost digits. A
  number parameter is carried as text and bound exactly (int8 or NUMERIC on
  PostgreSQL, a decimal string on MySQL, `Numeric` on SQL Server).
- A dropdown item that closed its own view crashed the window
  (`DropdownMenu` now tolerates its element being gone).

## Phase 11

- **Import/Export Connections** (File menu, palette): a JSON file with every
  setting and no secrets (`profiles/transfer.rs`). Imported connections ask
  for passwords on first connect; a clashing name gets " (imported)"; a bad
  entry is skipped and named.
- **Reconnect in place** after a lost connection, from the failed result or
  table. It never re-runs the statement that failed.
- **New Window** (⇧⌘N). Windows are `workspace-N` (capability covers
  `workspace-*`); menu commands go to the focused window only; only the
  main window saves and restores tabs; tab ids are unique across windows,
  since each names its own database session.
- Mutual TLS is now proven against a PostgreSQL server that demands a client
  certificate (`mutual_tls` in tests/drivers.rs; certificates generated by
  `scripts/integration-tests.sh`). MySQL and SQL Server still rely on the
  driver APIs (decision 0021).

## Phase 12

- Filters: an on/off box per row, Apply All (Mod+Return), Show SQL (the
  WHERE clause Rust builds), Filter by / Exclude This Value from a cell.
- Foreign keys: "Open … Row" from a foreign key cell, "Rows in child.column"
  from a referenced cell (`list_referencing`, single-column keys). The
  other table opens already filtered.
- Editing: Duplicate Rows (Mod+D), Paste as New Rows (Mod+V, TSV or CSV),
  Set to DEFAULT, undo/redo of staged edits (Mod+Z / Mod+Shift+Z). Clipboard
  read needed `clipboard-manager:allow-read-text`.
- Value display: a JSON tree, image preview for PNG/JPEG/GIF/WebP, hex dump
  and base64 for binary, and a display time zone (Settings) applied only to
  values that carry an offset. Binary values up to 64 KB travel to the grid
  in full (`Cell::Binary.inline`) so they can be previewed and copied.
- Excel export: `rust_xlsxwriter` (constant-memory mode, streams rows);
  numbers are written as numbers only when that keeps every digit.

## Phase 13

- Query parameters are wired end to end: `:name`, `?` (MySQL, SQL Server)
  and `$1` (PostgreSQL) are found, asked for once in a form with a type
  (text, number, NULL), remembered per tab, and bound by the driver.
  `@name` is not a placeholder (it is a variable in MySQL and T-SQL) and `?`
  is not one on PostgreSQL (a JSON operator). History keeps the statement
  with placeholders, never the values.
- Autocomplete from a per-connection, per-database schema cache
  (`completion_schema`); CodeMirror resolves aliases. Refreshing the
  explorer clears the cache.
- Format (Mod+I) and Minify with `sql-formatter` (loaded on first use).
- EXPLAIN (⇧⌘E) on all three engines into one tree (`database/plan.rs`),
  most expensive steps marked; EXPLAIN ANALYZE on PostgreSQL runs in a
  separate session inside a rolled-back transaction and asks first.
- Every row set of a batch is kept and shown as its own result.
- Results stream: the UI polls `query_progress` for rows so far and the
  first rows while a query runs; a cancel or timeout keeps the rows that
  had arrived (`error.data.partial`).
- Split Editor (⇧⌘D), snippet keywords on saved queries (`${name}` fields),
  Open SQL File (⌘O, up to 5 MB) and Run SQL File (statement splitting in
  Rust with DELIMITER, GO and `$$`; stops at the first error with its line).
  Run SQL File refuses read-only connections and always asks first.
- Editor settings: font, indentation, keyword case, word wrap, Vim
  (`@replit/codemirror-vim`, loaded only when turned on).
- Charts: bars or a line from a query result's first 500 rows.

## New dependencies

- `rust_xlsxwriter` 0.99 (`constant_memory`): Excel export.
- `sql-formatter` 15.9.0 (MIT): Format SQL.
- `@replit/codemirror-vim` 6.4.0 (MIT): Vim key bindings.

## Verified

`npm run check` passes (212 frontend, 135 Rust unit tests). 78 integration
tests pass on MySQL 8.4, PostgreSQL 16 and SQL Server 2022, including new
ones for bound parameters with big integers on all three engines, filters
and full binary in exports, enum/foreign key/referencing metadata,
autocomplete schema, plans for a join, ANALYZE rolling back, multiple row
sets, rows kept after a cancel, SQL files with engine syntax, editing a
query result, and mutual TLS.

## Not done

- Autocomplete timing on a 500-table schema hasn't been measured; the
  schema is cached so typing never waits on the server.
- "Show Referencing Rows" covers single-column foreign keys only.
