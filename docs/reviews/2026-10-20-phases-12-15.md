# Review of Phases 12–15 (2026-10-20)

A supervision pass over Phases 12–15 against `plan.md` §7b, on branch
`review-phases-12-15` (cut from `main` at `83a1dc9`).

**Starting point:** `npm run check` passes (348 frontend tests, 215 Rust
tests). `npm run test:integration` passes against MySQL 8.4, PostgreSQL 16
and SQL Server 2022: 96 tests.

## Overall

The work that exists is careful. Generated SQL is quoted per engine, the SQL
shown is the SQL that runs, and the integration tests apply real DDL on all
three engines and read it back. Commit messages and `plan.md` are honest
about what is unfinished. The problems are mostly what isn't built yet, plus
a few safety gaps where new write paths skipped rules that older ones follow.

## Phase 12 — Table data and results: done

All tasks are built and tested, including paging through a composite-key
table on each engine, editing query results, every copy/export format and
`.xlsx`.

- Minor: no integration test sorts a column containing NULLs on the server.

## Phase 13 — Smart SQL editor: done

All tasks are built. Bound parameters are proven verbatim (quotes and `;`).
Plans for a join render on all three engines. Every row set is kept, and
partial rows survive a cancel.

- Minor: the "within 100 ms for a 500-table schema" autocomplete criterion
  has no test.

## Phase 14 — Schema and object management: partly done

**Built:** DDL generation per engine; the Create Table wizard; the structure
designer (columns, indexes, primary key, single-column foreign keys); whole-
table actions (rename, duplicate, duplicate with data, empty, drop) confirmed
by typing the name; the ER diagram with SVG export; the review dialog.

**Safety gaps in what is built** (fixed on this branch):

1. Dropping a column, index or key in the designer runs after the SQL review
   alone, without naming the table. This breaks the exit criterion "no
   destructive object action runs without naming the object".
2. On a read-only connection, **New Table** is still offered in the explorer.
   No Rust command that applies DDL, table actions or row edits checks
   read-only mode. MySQL and PostgreSQL sessions refuse the writes anyway,
   but SQL Server has no read-only session, so the app check is its only
   guard.
3. The foreign key form makes you type the referenced table by hand, and
   silently uses `id` when no referenced column is given. It offers
   `RESTRICT` and `SET DEFAULT` on every engine, but SQL Server rejects
   `RESTRICT` and MySQL (InnoDB) rejects `SET DEFAULT`.
4. Check constraints are generated in Rust but can't be added from the UI.
5. Three components are over the 250-line limit: `CreateTableDialog.vue`
   (293), `ObjectView.vue` (289) and `DiagramView.vue` (266).

**Not built yet:** multi-column foreign keys; column reorder (MySQL);
functions, procedures, triggers, sequences, materialized views and types in
the explorer, with their definitions, and editing them; Show CREATE; SELECT,
INSERT, UPDATE and DELETE templates; creating and dropping databases and
schemas; PNG export of the diagram.

## Phase 15 — Import, export, backup and administration: mostly not built

**Built:** a SQL export ("Create Backup…") that Thabi generates itself, for
structure, data or both, streamed and cancellable. It is proven to restore
through Run SQL File on all three engines.

**Not built yet:** CSV, TSV and JSON import; an import-oriented "Run SQL dump"
dialog; backup and restore with the native tools (`pg_dump`, `mysqldump`,
SQL Server `BACKUP DATABASE`); users and permissions; server activity
(process list and kill); storage overview; the metrics board.

## Plan for this branch

1. Fix the Phase 14 safety gaps (items 1–3) and enforce read-only mode in
   Rust.
2. Add check constraints to the designer, split the oversized components,
   and add the missing tests for NULL sorting and autocomplete speed.
3. Build the missing Phase 14 features: Show CREATE and templates; database
   and schema actions; the other object types and their definitions; multi-
   column foreign keys.
4. Build Phase 15, in this order: server activity and kill, the storage
   overview, CSV/TSV/JSON import, the "Run SQL dump" dialog, native backup
   and restore, and users and permissions. The metrics board, marked
   optional in the plan, comes last.

## Outcome (2026-10-23)

Items 1–4 of the plan above are done; see `docs/decisions/0036`. Every
Phase 14 gap is closed, and Phase 15 is built except the optional metrics
board. Along the way the review found and fixed bugs the earlier work had
missed: the Create Table wizard and its New Table button never worked;
MySQL rename, retype and comment changes dropped `NOT NULL` and defaults;
SQL Server `DROP INDEX` and `SET DEFAULT` were invalid; composite unique
indexes were mangled in SQL exports; MySQL bound-query results showed raw
binary.

Not done: the metrics board, a million-row import test, and a timing test
for autocomplete on a 500-table schema.
